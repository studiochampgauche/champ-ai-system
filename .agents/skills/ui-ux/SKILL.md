# UI / UX Design — Premium Digital Quality

## Objective
Deliver distinctive, considered interfaces that make complex products understandable and pleasant to use. Beautiful must also mean legible, accessible, stable and effective.

## Process
1. Learn product goals, user roles, key flows, required content, brand constraints and existing design system.
2. Map navigation and information architecture before composing screens; surface decisions, errors and irreversible actions clearly.
3. Establish design tokens: typography scale, spacing, colors, elevation, radii, responsive breakpoints and motion language.
4. Design real states: first visit, empty, loading, validation, error, success, dense data and edge cases.
5. Assess layouts at useful mobile, tablet and desktop sizes, with long text and translated strings.
6. Refine details: alignment, typography rhythm, contrast, animation timing, icons and touch/keyboard behavior.
7. Compare rendered UI against intended design; fix visible inconsistencies rather than simply reporting them.

## Standards
- Avoid generic template aesthetics and arbitrary decorative choices; establish hierarchy and purposeful visual identity.
- Motion must reinforce understanding. Use GSAP for complex orchestration where justified; integrate `gsap-react`, `gsap-performance` and reduced-motion considerations.
- Preserve accessibility; hover-only and mouse-only UI is incomplete.
- Reuse existing components and tokens unless there is a clear reason to redesign.
- Never generate a decorative showcase image just to announce task completion.

## Handoff
Provide design rationale, component states, breakpoints, checked interactions, accessibility findings and unresolved constraints.
